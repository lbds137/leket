0. From the checkout root (the base check in the placement section leaves you there), run `bash .claude/cloud/setup.sh 2>&1 | tee /tmp/cloud-setup.out | tail -40; echo "setup_rc=${PIPESTATUS[0]}" >> /tmp/cloud-setup.out`. The pipeline's own rc is `tail`'s, so the true exit code is appended as the log's final `setup_rc=` line: `setup_rc=2` (also visible as a `cloud setup: refusing` line) means the owner's-machine refusal fired — stop and report, and push nothing from that machine (the refusal exists because it is the owner's Deck); `setup_rc=1` means setup never reached the env-file step — a temp/write failure, or node 24 could not be provisioned (its log carries a `node install FAILED` line) — stop and report. (No plan-usage gate step here: unlike deck-platform, this repo ships no `bin/` gate tool; the launching session on the Deck runs its own usage gate before dispatching this unit.)
1. From then on, start every Bash call that runs a repo tool or test with `. /tmp/cloud-env.sh && `, from the checkout root. The Bash tool does not keep exports between calls. (When setup had to provision node, the file carries the PATH export that puts it first — source it even when it carries only comments, so the pattern holds when the suite grows its next export.)
2. In your report, carry every `install FAILED`, `npm ci FAILED`, and `oracle warmup FAILED` line, and every `MISSING` line that has NO matching `installed <pkg>` line after it — the checks run before the installs, so a tool can read MISSING and be installed a few lines later; the re-check's `<tool>: STILL MISSING after installs` line is the one that must not be ignored. Do not work around a missing tool in the repo's code.
3. On a stop with `setup_rc=1`, the run's verdict still travels through git. The results directory is `cloud-results/<run>/` on the `cloud-test/*` branch you were started on — `<run>` is that branch's name minus its `cloud-test/` prefix, which is the path suite.md's `@RESULTS@` interpolates to. `mkdir -p` it, write `git rev-parse HEAD` into it as `head.txt`, copy `/tmp/cloud-setup.out` beside it, add a `stopped.txt` carrying the `setup_rc=` line and the one-line stop reason, commit, push, and report the stop reason as the run's verdict. (`setup_rc=2` pushes nothing — see step 0.)
